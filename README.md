# Schedule-Aware Irrigation Fault Diagnosis

This repository contains a simulation-based university prototype for distinguishing normal irrigation operation, pipe leaks, and clogged emitters or sprinkler heads.

## Scope

- The study area is a 3 km radius around UOW Dubai, used as geographic context only.
- The simulated irrigation network has three generic irrigation sectors (Zones A, B, and C). They are not mapped to named parks and do not represent the university's real pipes or irrigation equipment.
- `uow_study_area_map.html` is a self-contained offline schematic showing the 3 km study radius and hypothetical node locations. It does not use street-map tiles or represent actual pipe locations.
- UOW Dubai is used only as a geographic reference point; its official contact page lists the campus address in Dubai Knowledge Park: [UOW Dubai contact page](https://www.uowdubai.ac.ae/contact-us).
- The intended model inputs are simulated pressure, flow, and watering-schedule information.
- The simulator currently includes illustrative morning, afternoon, and night demand profiles. Their multipliers are synthetic assumptions, not measured municipal schedules.
- The classifier will be compared with a schedule-aware threshold alert using the same test scenarios.
- Pipe dimensions and demands are prototype assumptions selected to produce visible simulated hydraulic changes; they are not calibrated field values.

## Setup

Use 64-bit Python 3.13. Create an isolated environment and install the listed packages:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## Normal simulation across schedules

Run the normal three-zone simulation for morning, afternoon, and night profiles:

```powershell
.\.venv\Scripts\python.exe .\first_simulation.py
```

The network parameters are illustrative assumptions, not field measurements. See [DEVELOPMENT_LOG.md](DEVELOPMENT_LOG.md) for progress and evidence notes.

## Fault comparison across schedules

Run one selected normal, leak, or clog case for any zone and schedule. Add `--all-hours` to display the full six-hour profile. For example:

```powershell
.\.venv\Scripts\python.exe .\fault_scenarios.py --condition leak --severity moderate --zone Zone_A --schedule afternoon --all-hours
```

This comparison uses illustrative leak emitter coefficients and reduced zone demand as a simple clog surrogate. These fault settings require further review before they are used to generate classifier training data.

## Normal watering scenarios

Generate the full six-hour normal-operation readings for all schedules and zones:

```powershell
.\.venv\Scripts\python.exe .\watering_scenarios.py
```

To generate only one profile, add `--schedule morning`, `--schedule afternoon`, or `--schedule night`. The script saves a labelled CSV in `outputs/`. The baseline file `outputs/normal_watering_scenarios.csv` is shared through GitHub and displayed in the dashboard; other generated files under `outputs/` remain ignored.

## Full labeled scenario dataset

Generate normal, leak, and clog data for every schedule, zone, and severity:

```powershell
.\.venv\Scripts\python.exe .\generate_labeled_dataset.py
```

This creates 342 schedule-hour records from 57 scenario configurations and saves the shared dataset to `outputs/labeled_fault_scenarios.csv`. Column meanings and split guidance are in [DATA_DICTIONARY.md](DATA_DICTIONARY.md).

## Streamlit prototype views

Start the local dashboard with:

```powershell
.\.venv\Scripts\python.exe -m streamlit run .\app.py
```

The dashboard contains a study-area view, a hypothetical pipeline view, and a filterable table of the labeled scenario dataset. The study-area view can display Google satellite imagery with simulated pipe overlays when a Google Maps JavaScript API key is configured; without a key, it falls back to the offline illustration. The pipes and readings are generated by the simulation, not taken from UOW infrastructure. The classifier is not connected yet.

To enable satellite imagery locally, copy `.streamlit/secrets.toml.example` to `.streamlit/secrets.toml` and add your Google Maps API key there. Keep the real `secrets.toml` out of GitHub. The app also reads `GOOGLE_MAPS_API_KEY` from an environment variable, which can be set in Render's Environment settings at deployment time. Google requires an API key for Maps JavaScript API; billing must be enabled for a standard key. A restricted no-cost demo key is also available for prototyping. See [Google Maps API key setup](https://developers.google.com/maps/documentation/javascript/get-api-key), [demo key setup](https://developers.google.com/maps/documentation/javascript/demo-key), and [Render environment variables](https://render.com/docs/configure-environment-variables).

### Future Render deployment

The current app can be deployed later as a Render Web Service. Suggested build command: `pip install -r requirements.txt`. Suggested start command: `streamlit run app.py --server.address 0.0.0.0 --server.port $PORT`. Add `GOOGLE_MAPS_API_KEY` as a Render environment variable; do not place the key in GitHub.
